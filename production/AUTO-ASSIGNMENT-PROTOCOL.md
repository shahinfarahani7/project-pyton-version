# Automatic Worker Assignment Protocol

## Canonical decision

EdgeMint does not ask a worker to accept or reject each task. A worker opts in globally by holding current consent and setting the app to **Available**. While Available, the server may assign compatible work automatically. The Available preference is account-wide for the worker; each device must also independently be online, attested, healthy, within schedule, and have free capacity before it can receive a lease.

## Atomic server action

The router performs worker eligibility, deterministic ranking, capacity reservation, assignment creation, lease creation, fence-token allocation, attempt transition from `matching` to `leased`, and transactional outbox insertion in one authoritative PostgreSQL transaction. There is no intermediate offer state.

## Delivery and start

The assignment is targeted to exactly one worker device over durable WebSocket delivery. The WebSocket ACK is generated by the client protocol stack and means only **the frame was durably received**. It never means the worker or user approved execution.

After validating event signature, device binding, current lease, fence token, model digest, input digest and execution limits, the Worker Agent starts the task automatically and calls `reportAssignmentStarted`. No UI prompt or user action is allowed.

## Changed local conditions

A device can become unsuitable after routing but before execution. The Worker Agent may call `reportAssignmentUnavailable` only for a machine-detected reason from the canonical enum: `battery_low`, `thermal_block`, `network_policy_blocked`, `model_unavailable`, `insufficient_storage`, `runtime_incompatible`, or `resource_pressure`. Free-text and user-selected rejection reasons are forbidden.

The server validates the lease and fence, records the reason, revokes or fails the assignment, returns the attempt to matching when retry policy allows, and creates any replacement lease with a strictly higher fence token. Validated environmental unavailability is worker-neutral; repeated anomalous reporting feeds reliability and fraud analysis.

## Timeout behavior

- WebSocket delivery timeout causes delivery retry and replay under the durable event protocol.
- Failure to report automatic start before `autoStartGraceSeconds` expires causes the current lease to be revoked or expired and the attempt to return to matching.
- Lease renewal remains automatic while execution is active.
- A stale worker result is retained only as rejected evidence and never creates billing or reward.

## Worker controls

The worker can set the application to `Unavailable` before receiving new work. Changing availability does not cancel an already leased task; active execution follows the documented safe-stop, checkpoint, failure, and reassignment rules. There is no per-task Accept or Reject control.

## Forbidden implementation

The following are release blockers:

- `offered`, `accepted`, or `rejected` assignment states;
- per-task Accept or Reject buttons;
- `acceptAssignment` or `rejectAssignment` APIs;
- offer or acceptance timeout configuration;
- treating WebSocket ACK as execution consent;
- broadcasting a task to multiple ordinary workers outside explicit consensus fan-out.

## Availability changes after assignment

`Available` and schedule settings gate only the creation of future leases. Switching to `Unavailable` after a lease exists does not cancel, reject or revoke that assignment. The Worker Agent continues under the current lease and fence until completion, a validated machine-only unavailability condition, lease expiry, or a server security/policy revocation. This prevents the global availability switch from becoming a per-task Reject control.

## Delivery and automatic-start deadlines

`assignmentDeliverySeconds` is the bounded time for targeted WebSocket delivery or pull fallback. `autoStartGraceSeconds` begins only after that delivery window. Therefore `startDeadlineAt = assignedAt + assignmentDeliverySeconds + autoStartGraceSeconds`; it is never earlier than `deliveryDeadlineAt`. Missing a delivery ACK does not ask the Worker for consent. If the Agent has not started by the combined deadline, the lease is expired and reassigned automatically with a higher fence token.
