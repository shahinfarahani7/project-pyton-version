## ۱. هدف این سند

این سند توضیح می‌دهد **FibonAI به‌عنوان یک کسب‌وکار چیست**، **چه کسانی از آن استفاده می‌کنند**، **کار و ارزش چگونه جریان دارد**، و **کدام قواعد ثابت است**. برای کار تحلیل: ردیابی نیازمندی‌ها، مدل فرایند، مصاحبه ذی‌نفعان، تحلیل شکاف و بازبینی انطباق نوشته شده است.

این سند **جایگزین** متون حقوقی، مشخصات کامل معماری یا شواهد امضاشده تولید نیست.

> **دو لایه را جدا نگه دارید.** **مدل کسب‌وکار** (وایت‌پیپر، [FibonAI-Business-Model.fa.md](../business/FibonAI-Business-Model.fa.md)) شامل اعتبار رایگان ماهانه، اعتبار توکنی و پاداش توکن FibonAI است و **هرگز قیمت به مشتری نشان نمی‌دهد**. **کد فعلی و اسناد فنی فریزشده** (GA1) هنوز پیش‌فاکتور داخلی یورویی و پاداش یورویی دارند و توکن در آن‌ها غیرفعال است. شکاف‌ها در §۱۲ و جدول تعارض مدل کسب‌وکار آمده است. نیازمندی‌های مدل توکنی به بازنگری نسخه ۳ معماری و تأیید حقوقی نیاز دارد.

## ۲. خلاصه مدیریتی

FibonAI یک **شبکه‌ی غیرمتمرکز اجرای هوش مصنوعی** با مدلی متمایز است:

1. درخواست‌دهنده **هر ماه تعدادی درخواست رایگان** دارد و پس از آن **اعتبار ماهانه را با توکن FibonAI** می‌گیرد. **هیچ قیمتی به مشتری نشان داده نمی‌شود** — فقط اعتبار.
2. هر درخواست یک **ارزیابی سریع** از سختی و زمان می‌گیرد و سپس به **حداقل ۳ موبایل داوطلب** (Worker) ارسال می‌شود.
3. پلتفرم **پاسخ‌ها را با اجماع مقایسه** می‌کند و پاسخ مورد توافق را برمی‌گرداند؛ موبایل‌هایی که درست پاسخ داده‌اند **توکن FibonAI** می‌گیرند.
4. FibonAI **هیچ ذخیره‌ی مرکزی از اطلاعات محرمانه‌ی مشتری ندارد** و **هر گام قابل ممیزی است** (تخصیص، اعتبارسنجی، اعتبار، پاداش).

**پیام:** هوش مصنوعی غیرمتمرکز و حریم‌خصوصی‌محور روی موبایل‌های روزمره — نه استخراج رمزارز، نه درآمد تضمینی، نه محصول سرمایه‌گذاری.

## ۳. مسئله و ارزش کسب‌وکار

### ۳.۱ مسئله مشتری

افراد و سازمان‌ها به OCR، استخراج، طبقه‌بندی، خلاصه‌سازی، ترجمه و ویرایش عکس/ویدیو نیاز دارند، اما نمی‌خواهند:

- هزینه‌ی سنگین زیرساخت متمرکز بپردازند
- داده‌شان به‌صورت متمرکز ذخیره، فروخته یا سوءاستفاده شود
- نتیجه‌ای بگیرند که نمی‌توانند به آن اعتماد یا آن را ممیزی کنند

### ۳.۲ ارزش برای مشتری

| ارزش | تحویل FibonAI |
| --- | --- |
| **شروع رایگان** | درخواست رایگان ماهانه؛ پیشنهاد شروع: یک ماه رایگان + API رایگان |
| **اعتبار ساده** | مشتری فقط اعتبار باقی‌مانده و مصرف‌شده را می‌بیند (درجه سختی × تسک پایه)، هرگز قیمت |
| **نتیجه‌ی قابل اعتماد** | هر تسک با حداقل ۳ موبایل بررسی می‌شود؛ فقط پاسخ اجماعی برمی‌گردد |
| **حریم خصوصی** | بدون ذخیره‌ی مرکزی؛ Payload حداقلی؛ انتقال رمزنگاری‌شده |
| **ممیزی‌پذیری** | دفتر کل زنجیره‌هش از چرخه کار، اعتبارسنجی، اعتبار و پاداش |
| **یکپارچه‌سازی** | REST API، webhook، پورتال مشتری؛ چرخه کار ناهمزمان |

### ۳.۳ ارزش برای Worker (عرضه)

مالک گوشی با **رضایت صریح** (حداقل ۴ گیگابایت RAM و ۴ گیگابایت فضای خالی) در محدودیت‌هایی که خود تنظیم می‌کند (باتری، Wi‑Fi، دما) به کارهای تخصیص‌یافته کمک می‌کند. Workerهایی که پاسخشان با اجماع یکی است **توکن FibonAI** می‌گیرند (قواعد تقسیم در §۷ مدل کسب‌وکار). پاداش تضمین‌شده نیست.

### ۳.۴ ارزش برای اپراتور

تیم داخلی مسیریابی، کلاهبرداری، تطبیق، پشتیبانی Worker و حوادث را از **کنسول عملیات** با همان دفتر کل ممیزی انجام می‌دهد.

## ۴. ذی‌نفعان و پرسونا

| ذی‌نفع | نمونه پرسونا | اهداف اصلی |
| --- | --- | --- |
| **سازمان مشتری** | مالی، مهندس یکپارچه‌سازی، انطباق | ارسال کار، مدیریت اعتبار، اثبات «چه کسی کجا اجرا کرد» |
| **کاربر عمومی** | ترجمه‌ی متن یا ویرایش عکس | آپلود → نتیجه، در محدوده‌ی اعتبار رایگان |
| **Worker** | کاربر اپ اندروید | کنترل زمان کار دستگاه؛ توکن برای تسک صحیح؛ پاداش تضمین‌شده نیست |
| **اپراتور** | پشتیبانی، fraud، مالی، SRE | رفع خطا، تطبیق پاداش، اجرای سیاست |
| **خزانه / حاکمیت** | دارندگان توکن بیش از حد معین | تصمیم درباره‌ی سوزاندن، توسعه یا حمایت از پاداش |
| **شرکت سرمایه‌گذاری مادر** | تیم مؤسس | سهم سالانه با همان فرمول Workerها |
| **صرافی‌ها / هویت** | صرافی‌های DEX/CEX؛ احراز هویت | تهیه‌ی توکن توسط درخواست‌دهنده؛ تأیید Worker |
| **ممیز خارجی** | ممیز مشتری | شواهد سیاست، مصرف اعتبار و داده |

**مرزهای اعتماد (برای نیازمندی‌ها):**

- ورودی مشتری تا پیش از اعتبارسنجی **غیرقابل اعتماد** است.
- دستگاه Worker و نتیجه ارسالی تا تأیید سرور **غیرقابل اعتماد** است.
- **هویت مشتری به Worker نشان داده نمی‌شود**؛ ورودی‌های موقت حداکثر **۱۵ دقیقه** نگه داشته می‌شوند.

| حوزه | در GA1 | یادداشت برای BA |
| --- | --- | --- |

| کاتالوگ کار (OCR، سند، بینایی، NLP و …) | بله | **۵۶ نوع**؛ همه handler اختصاصی روی دستگاه ندارند |
| اپ Worker (اول اندروید) | بله | رضایت، UI درآمد، gamification بدون قمار |
| مسیریابی لبه + fallback ابر | بله | fallback باید ثبت شود |
| اعتبار مشتری (کد فعلی: EUR؛ مدل کسب‌وکار: رایگان ماهانه + توکنی) | بله | فقط واحد صحیح؛ هرگز به‌صورت قیمت نمایش داده نمی‌شود |
| پاداش Worker (کد فعلی: EUR؛ مدل کسب‌وکار: توکن FibonAI) | بله | پاداش توکنی نیازمند معماری v3 + تأیید حقوقی |
| کنسول عملیات | بله | ممیزی، fraud، تطبیق |
| فروش عمومی توکن / تسویه on-chain | **خیر (GA1)** | مدل کسب‌وکار لیست در صرافی را برنامه دارد؛ نیازمند v3 + حقوقی |
| انتشار مدل بدون مجوز | **خیر** | فقط کاتالوگ تأییدشده |
| آموزش روی دستگاه Worker | **خیر** | فقط inference |
| تقسیم یک inference روی چند گوشی | **خیر** | اجماع **کل** تسک را به ۳+ موبایل می‌فرستد، آن را تقسیم نمی‌کند |
| محاسبه پنهان پس‌زمینه | **خیر** | اجرای قابل‌مشاهده در اندروید |

**وضعیت توکن:** وایت‌پیپر توکن FibonAI را هسته‌ی اقتصاد می‌داند (عرضه‌ی ثابت ۲۱ میلیارد، پاداش اجماعی). **تصمیم canonical فریزشده‌ی GA1 هنوز توکن را غیرفعال می‌داند.** نیازمندی‌های توکنی را **دامنه‌ی هدف در انتظار معماری v3 و تأیید حقوقی** در نظر بگیرید. در هیچ متنی ارزش، قیمت، سود یا سرمایه‌گذاری توکن را بیان نکنید.

### ۶.۲ قواعد کسب‌وکار (BR)

| شناسه | قاعده | دلیل |
| --- | --- | --- |
| BR-01 | **هیچ قیمتی به مشتری نشان داده نمی‌شود.** اعتبار مصرفی (K × تسک پایه) پس از صدور ارزیابی ثابت است | قاعده‌ی مشتری؛ مصرف قابل پیش‌بینی |
| BR-02 | **فقط پلتفرم** زمان‌بندی، retry، تخصیص مجدد و fallback را تصمیم می‌گیرد | جلوگیری از orchestration روی Worker |
| BR-03 | Worker در پروتکل تولید **Accept/Reject** هر کار ندارد | مدل رضایت: opt-in + availability |
| BR-04 | **دقیقاً یک** تکمیل پذیرفته و **یک** کسر اعتبار به ازای revision | یکپارچگی اعتبار |
| BR-05 | **دقیقاً یک** پاداش برای هر Worker هم‌نظر در هر تسک؛ Worker غیرهم‌نظر چیزی نمی‌گیرد | یکپارچگی پاداش |
| BR-06 | fallback ابر **هرگز پنهان نیست** | انطباق و اعتماد |
| BR-07 | پاداش Worker **متغیر و تضمین‌شده نیست** | شرایط Worker |
| BR-08 | پلتفرم **استخراج رمزارز نیست** | guardrail بازاریابی |
| BR-09 | ورودی موقت مشتری **ظرف ۱۵ دقیقه حذف** | حریم خصوصی |
| BR-10 | **بدون ادعای قیمت، ارزش، سود یا سرمایه‌گذاری توکن** در هیچ متنی | سلب مسئولیت وایت‌پیپر؛ canonical-decisions |
| BR-11 | هر تسک به **حداقل ۳ Worker** می‌رود؛ نتیجه فقط با اجماع پذیرفته می‌شود (حداقل ۲ از ۳، یا اکثریت در مراحل بعد؛ حداکثر ۱۰ مرحله) | نتیجه‌ی قابل اعتماد |
| BR-12 | تقسیم پاداش: ۳ از ۳ → هرکدام ۲۵٪ X + ۲۵٪ خزانه؛ ۲ از ۳ → هرکدام ۲۵٪ + ۵۰٪ خزانه؛ مراحل بعد → ۷۵٪ مساوی بین هم‌نظرها + ۲۵٪ خزانه | §۷ وایت‌پیپر |
| BR-13 | Worker فریبکار یا تنبل اخطار می‌گیرد و در تکرار **به‌طور خودکار حذف** می‌شود | یکپارچگی شبکه |

### ۶.۳ مسیرهای استثنا

| استثنا | رفتار پلتفرم | نتیجه برای مشتری |
| --- | --- | --- |
| Worker واجد شرایط نیست | صف، retry یا fallback | تأخیر یا fallback با دلیل |
| نبود اجماع | +۲ Worker جدید در هر مرحله، حداکثر ۱۰ مرحله | تأخیر؛ پس از ۱۰ مرحله بازگشت بدون نتیجه |
| از دست رفتن رضایت میانه کار | توقف؛ تخصیص مجدد یا شکست | وضعیت + رویداد ممیزی |
| شکست تأیید | retry/ارتقا طبق سیاست | failed یا escalated |
| اتمام اعتبار | رد درخواست؛ پیشنهاد اعتبار ماهانه‌ی توکنی | پیام واضح (بدون قیمت) |
| انقضای ارزیابی قبل از تأیید | رد تأیید؛ ارزیابی جدید | خطای واضح |
| کشور پشتیبانی‌نشده Worker | درآمد Worker غیرفعال | — |
| ارسال تکراری (idempotency) | همان هویت منطقی کار | بدون کسر دوباره |

## ۷. کاتالوگ محصول (نمای کسب‌وکار)

| دسته | نمونه کار | ورودی |
| --- | --- | --- |
| هوش سند | OCR، استخراج، verify | PDF، تصویر |
| بینایی و کاتالوگ | classify، tag، safety، حذف پس‌زمینه | تصویر |
| زبان و NLP | خلاصه، ترجمه، moderation، همراهی در نوشتن مقاله | متن |

- کاتالوگ **۵۶ نوع**؛ بسیاری روی pipeline مشترک Worker نگاشت می‌شوند.
- **هیچ قیمتی منتشر یا نمایش داده نمی‌شود.** هر تسک **K × تسک پایه** اعتبار مصرف می‌کند؛ K درجه‌ی سختی از ارزیابی سریع است.
- **دقت OCR** روی رسید واقعی **پذیرش جدا** از «JSON معتبر API» است.

| پیام | تضمین‌شده نیست، درآمد منفعل نیست، ماینینگ نیست | همان |

### ۸.۳ اقتصاد توکن (خلاصه)

عرضه‌ی ثابت ۲۱ میلیارد، بدون ضرب جدید؛ ۱۶ میلیارد برای مشارکت‌کنندگان با مدل انتشار توانی بی‌نهایت فیبوناچی (توان ۰٫۲۵؛ حدود ۱٫۸۸ میلیارد در سال اول)؛ ۵ میلیارد برای شرکت سرمایه‌گذاری مادر و دارندگان توکن با همان زمان‌بندی سالانه؛ خزانه ۲۵٪ هر توزیع پاداش به‌علاوه‌ی توزیع مصرف‌نشده را می‌گیرد و حاکمیت درباره‌ی سوزاندن، توسعه یا سپرده‌گذاری تصمیم می‌گیرد.

### ۸.۴ ممنوع در هر متن مشتری یا فروش

- هر قیمت برای تسک (یورو، دلار یا توکن)، جدول نرخ یا مبلغ پیش‌فاکتور
- قیمت توکن، پیش‌بینی ارزش، APY، سود، «سرمایه‌گذاری» یا درآمد از کار دیگران
- درآمد تضمینی Worker یا استعاره mining

دعوت از دیگران **برای ادامه‌ی چرخه‌ی شبکه** تشویق می‌شود، بدون ادعای درآمد.

## ۹. تأیید و کیفیت

در مدل کسب‌وکار **اجماع پیش‌فرض است**: هر تسک به حداقل ۳ Worker مستقل می‌رود.

| سطح (مفهومی) | معنی کسب‌وکار |
| --- | --- |
| Consensus (پیش‌فرض) | حداقل ۳ Worker مستقل؛ قواعد anti-affinity؛ تا ۱۰ مرحله +۲ Worker |
| Standard (پیش‌فرض کد فعلی) | یک مسیر تأیید |
| Human review | وقتی خودکار کافی نیست |

نتیجه‌ی تأیید باید به **کسر اعتبار**، **تقسیم پاداش** و **رویداد ممیزی** وصل شود.

## ۱۱. چک‌لیست انطباق پیام

- [ ] **هیچ قیمتی** (یورو، دلار، توکن) به مشتری نشان داده نمی‌شود — فقط اعتبار
- [ ] اعتبار مصرفی تسک **قبل** از تأیید اجرا نمایش داده می‌شود
- [ ] دلیل fallback **قابل مشاهده**
- [ ] متن Worker: پاداش **متغیر / تضمین‌شده نیست**
- [ ] بدون زبان **ارزش توکن، سرمایه‌گذاری، سود** یا **mining**
- [ ] هر جا از توکن نام برده شود، سلب مسئولیت (مدل کسب‌وکار §۱۱.۴) آمده باشد
- [ ] سیاست اقامت داده در صورت نیاز
- [ ] ارجاع DPA، حریم خصوصی، شرایط Worker برای امضای حقوقی

## ۱۳. واژه‌نامه

| اصطلاح | معنی کسب‌وکار |
| --- | --- |
| **Task** | درخواست یک واحد کار AI (هویت پایدار) |
| **Revision** | نسخه immutable ورودی/تنظیمات |
| **Assessment (ارزیابی)** | برآورد سریع درجه سختی K و زمان؛ اعتبار مصرفی را ثابت می‌کند (کد فعلی: پیش‌فاکتور داخلی EUR، نمایش داده نمی‌شود) |
| **Consensus (اجماع)** | توافق نتایج Workerهای مستقل؛ تنها راه پذیرش نتیجه |
| **تسک پایه / K** | واحد اعتبار؛ تسک با سختی K معادل K تسک پایه است |
| **توکن FibonAI** | توکن شبکه (عرضه‌ی ثابت ۲۱ میلیارد) برای پاداش Worker و اعتبار درخواست‌دهنده — بدون ارزش تضمین‌شده |
| **خزانه** | ذخیره‌ی تحت حاکمیت جامعه که ۲۵٪ هر توزیع پاداش را می‌گیرد |
| **Policy hash** | اثر انگشت سیاست برای ممیزی |
| **Assignment** | دستور پلتفرم به یک Worker برای یک attempt |
| **Lease / fence** | حق انحصاری اجرا؛ fence از overwrite قدیمی جلوگیری می‌کند |
| **Verification** | تصمیم پلتفرم درباره کیفیت/یکپارچگی |
| **Cloud fallback** | اجرا در ابر تأییدشده وقتی لبه کافی نیست |
| **اعتبار تسک** | سهمیه‌ی مشتری: درخواست رایگان ماهانه + اعتبار ماهانه‌ی توکنی (کد فعلی: موجودی پیش‌پرداخت EUR) |
| **Reward micros** | فقط در کد فعلی: مبلغ EUR قابل پرداخت Worker، نه توکن |
| **Workspace** | مرز tenancy داده و اعتبار |
| **Edge / Worker** | دستگاه opt-in با مدل امضاشده |
| **GA1** | دامنه اولین عرضه تجاری |
