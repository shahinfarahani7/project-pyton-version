1. Purpose of this document

This brief explains what FibonAI is as a business, who uses it, how work and money flow, and which rules are fixed for the first commercial release (GA1). It is written for analysis work: requirements traceability, process models, stakeholder interviews, gap analysis, and compliance review.

It does not replace legal terms, the full architecture specification, or signed production evidence.

2. Executive summary

FibonAI is a B2B AI execution platform with a distinctive commercial model:

1. The customer sees a fixed price in euros before any task runs (“quote before run”).

2. Work is executed preferentially on opted-in mobile devices (edge workers), not only in a central cloud.

3. If edge capacity or policy blocks execution, cloud fallback is explicit — reason and cost are recorded; there is no silent reroute.

4. Every step is auditable for regulated teams (assignments, verification, billing, rewards, fallback).

Positioning (phase 1 messaging): edge-first AI inference with transparent pricing and auditable execution — not cryptocurrency mining, not guaranteed worker income, not token investment.

3. Business problem and value

3.1 Customer problem

Organizations need document, vision, and language AI (OCR, extraction, classification, summarization, moderation) without:

  • Surprise bills after jobs complete
    • Opaque routing (“where did my data go?”)
      • Weak audit trails for finance or compliance reviews

      3.2 Customer value

      ValueHow FibonAI delivers it
      Price certaintyImmutable EUR quote before confirmation; published unit rates as baseline
      Policy controlRegion / execution policies enforced at intake; cloud only when policy allows
      AuditabilityHash-chained ledger of task lifecycle, verification, billing, and fallback events
      IntegrationREST API, webhooks, customer portal; async task lifecycle

      3.3 Worker (supply-side) value

      Phone owners who opt in can contribute device compute to assigned tasks within limits they set (battery, Wi‑Fi, thermal). They receive variable EUR rewards (not tokens in GA1), subject to identity/payout eligibility.

      3.4 Operator value

      Internal teams run routing, fraud review, reconciliation, worker support, billing disputes, and incident response through an operations console, with the same ledger the customer audit uses.

          6.2 Business rules (must hold in requirements)

          IDRuleRationale
          BR-01Quote is immutable after issuance until expiry“Price first” promise
          BR-02Only the platform schedules, retries, reassigns, and decides cloud fallbackPrevents worker-side orchestration and fraud
          BR-03Worker does not accept/reject individual tasks in production protocolOpt-in + availability is the consent model
          BR-04Exactly one accepted completion and one customer charge per task revisionBilling integrity
          BR-05Exactly one reward credit per accepted worker contribution (per policy)Payout integrity
          BR-06Cloud fallback never silentCompliance and customer trust
          BR-07Worker rewards are variable, not guaranteedLegal / worker terms
          BR-08Platform is not crypto miningWorker terms and marketing guardrails
          BR-09Temporary customer inputs deleted within 15 minutesPrivacy by design
          BR-10GA1: no token sale, value, or investment claimscanonical-decisions.yaml

          6.3 Exception paths (BA should model)

          ExceptionExpected platform behaviorCustomer-visible outcome
          No eligible workerQueue, retry, or cloud fallback (if policy allows)Delay or fallback with reason
          Worker loses consent mid-runPause / terminate; server reassigns or failsTask state + audit event
          Verification failsRetry classification per policy; escalation tiersFailed or escalated status
          Quote expired before confirmReject confirm; new quote requiredClear error
          Unsupported worker countryEarning disabled for worker; task may still run on other workersN/A to customer
          Duplicate submission (idempotency)Same logical task identityNo double bill
